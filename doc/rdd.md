# プロフィールサイト 要件定義書 (v2.0)

v1.1 は Next.js + Python + Firestore + shadcn/ui + パスワード認証 + Firebase 無料枠という構成を前提にしていましたが、実装とも現在の方針とも一致しなくなったため全面的に改訂しました。改訂の経緯と技術判断の理由は [decisions.md](./decisions.md) に記録しています。

## 1. 概要

Y.Ohara の経歴・スキル・実績を紹介するプロフィールサイト。友人・知人への情報共有と、転職活動の補助を目的とします。

## 2. 開発方針

- **バックエンドを持たない。** 完全な静的サイトとして配信し、サーバーサイドの実行環境・認証基盤・データベースをいずれも持ちません。運用対象を減らすことが保守性に直結します。
- **無料で運用する。** GitHub Pages で配信し、外部の有料サービスを使いません。
- **更新は Git を通す。** コンテンツはリポジトリ内のファイルで管理し、`main` への push で自動デプロイします。

## 3. ターゲットユーザー

友人・知人、および転職先候補企業の採用担当者。

**掲載する情報はすべて公開前提とします。** 閲覧者によって内容を出し分けることはしません。

## 4. サイト構成

- **トップ（ヒーロー）:** 自身の写真、名前、簡単な自己紹介
- **プロフィール:** 学歴 / 職務経歴 / スキル / 趣味 / 実績（特許・論文・登壇）
- **ギャラリー:** 趣味で撮影した写真 9 枚（クリックで拡大表示）
- **共通:** ヘッダー（ナビゲーション・言語切替・テーマ切替）、フッター

## 5. 機能要件

- **多言語対応:** 日本語・英語の切り替え。翻訳は自身で行い、リポジトリ内のロケールファイルで管理する
- **テーマ切り替え:** ライト / ダーク。初回は OS の設定に追従し、以降は選択を保存する
- **レスポンシブデザイン:** PC・スマートフォンの双方でレイアウトが崩れないこと
- **ギャラリーの拡大表示:** キーボードのみでも開閉・前後移動ができること
- **アクセシビリティ:** 見出しの階層が正しいこと、操作要素に名前があること、`prefers-reduced-motion` を尊重すること

### 要件から外したもの

| 項目                                   | 理由                                                                                                                                                         |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| パスワード認証による職務経歴の詳細表示 | 静的サイトでは機密性を提供できない。実際、旧実装では詳細が認証前から JS バンドルに平文で含まれていた。掲載内容を公開可能な情報に限ることで要件自体を解消した |
| Firestore でのコンテンツ管理           | 更新頻度が半年に 1 回程度であり、ファイル編集 + push で十分。API 待ちの初期表示や無料枠の消費を避ける                                                        |
| アクセス解析                           | 計測しない方針とした                                                                                                                                         |
| 動画ページ                             | 掲載しない                                                                                                                                                   |

## 6. 技術構成

| 領域           | 採用                                                                               |
| -------------- | ---------------------------------------------------------------------------------- |
| ビルド         | Vite 6                                                                             |
| UI             | React 18 + TypeScript                                                              |
| スタイル       | Tailwind CSS 3（配色は CSS 変数によるトークン）                                    |
| アニメーション | framer-motion                                                                      |
| 多言語         | i18next / react-i18next                                                            |
| パッケージ管理 | pnpm（`packageManager` で固定）                                                    |
| 静的解析       | TypeScript / ESLint（型情報あり・react・jsx-a11y）/ Prettier / husky + lint-staged |
| テスト         | Playwright（デスクトップ・モバイルの 2 プロジェクト）                              |
| ホスティング   | GitHub Pages（プロジェクトページ `/my-profile-site/`）                             |
| CI/CD          | GitHub Actions                                                                     |

UI ライブラリ（shadcn/ui 等）は採用していません。必要なコンポーネントが `Container` / `Card` / `SectionHeading` / `ResponsiveImage` / `Lightbox` の 5 つに収まるため、素の Tailwind で足ります。

## 7. デザイン

- **雰囲気:** スタイリッシュ、モダン。写真を主役にする
- **配色:** `src/index.css` の CSS 変数で定義し、Tailwind からセマンティックな名前（`bg` / `surface` / `fg` / `accent` など）で参照する。ライトとダークの切り替えは変数の再定義だけで行う
- **フォント:** Inter を self-host（latin サブセットのみ）。日本語は端末のフォントに任せ、Web フォントは読み込まない
- **背景:** ヒーローに趣味の写真を使用し、グラデーションのスクリムでコントラストを確保する

## 8. パフォーマンス方針

写真主体のサイトなので、転送量を常に意識します。

- 画像は事前に WebP へ変換し、`srcset` で幅を出し分ける（`pnpm images:build`）
- アイコンフォントを CDN から読まない。必要な SVG だけをローカルに持つ
- 日本語 Web フォントを読み込まない
- `<img>` には必ず `width` / `height` を出してレイアウトシフトを防ぐ

現在の実測値（Pixel 5・初回表示）は約 0.59MB です。

## 9. コンテンツ更新

- **更新頻度:** 半年に 1 回程度
- **更新方法:** リポジトリ内のファイルを編集して `main` へ push（手順は README を参照）
- **日本語と英語は必ず対で更新する。** `en.ts` に `satisfies typeof ja` を付けているため、キー構造がずれると型エラーになります

## 10. 運用

- **公開範囲:** 全世界に公開
- **リポジトリ:** public（掲載内容がすべて公開前提であるため）
- **予算:** 無料
